# Downstream stable and nightly builds

**AI disclosure:** Prepared by Astra, an OpenAI AI assistant, at Felix Förtsch's direction.

## Source ownership

- `patch-queue` owns workflows, trusted publisher tooling and ordered accepted patches in `.github/downstream/patches/`.
- Nightly starts from the current upstream `main` commit and applies that queue.
- Stable starts from the latest upstream release tag and applies the same queue.
- Fork `main` is generated, validated nightly source plus trusted downstream tooling. It contains no workflows. Nightly updates it only under an explicit expected-SHA lease.
- `patch-queue` is the default branch so GitHub runs its six-hour schedule. `main` is generated source. Obsolete development branches were archived locally before removal; published tags remain unchanged.

Patch `0001-version-label.patch` shows upstream version plus queue count in the sidebar, without changing updater versions. Patch `0002-stack-game-copies.patch` groups matching cross-store games into one library card with a copy chooser. It includes matching regression tests and `doc/game-stacking.md` in generated source. Each store copy keeps its own game page, installation, settings and saves. Patch `0003-library-summary.patch` adds filtered library totals. Patch `0004-nile-session-recovery.patch` adds Amazon login/session recovery and persistent local logout; see generated `doc/nile-login.md`.

## Patch queue

Use ordered `NNNN-description.patch` files generated by `git format-patch`. Each file represents one coherent feature or fix, including its tests and documentation. Keep its AI disclosure in the opening commit-body paragraph.

Patch files are self-contained: the original commit named in their envelope need not exist in the `patch-queue` checkout. The builder reads the subject and diff from the file, applies it with `git am`, and records original and replayed source identities in `build-info.json`. A reverse-apply check detects an already-applied patch; conflicts stop the build rather than selecting ours or theirs.

Before accepting a patch, test it against both upstream main and the latest stable release. Preserve original feature commits in recoverable archives and keep published tags unchanged. Queue changes do not rewrite published releases.

## Automatic control refresh

Before channel builds, trusted current-control code reconstructs upstream default source plus the full queue, then restores only `.github/downstream`, the sole channel workflow, `.mise.toml`, downstream documentation, README prefix and documented Python ignore entries. Root `AGENTS.md` composes canonical fork agreement from `.github/downstream/AGENTS.md` with complete pristine upstream guidance. Reviewed upstream bytes live in `.github/downstream/upstream-AGENTS.md`; any new upstream guidance requires explicit policy review rather than silently importing restrictions. Fresh upstream README remains complete. Recorded repository/default ref/base detect ownership changes, rewinds and unknown source edits. No-op requires identical intended tree and upstream ancestry; control state has no run ID, wall clock or self-referential SHA.

Changed candidates receive a self-contained old-control bundle, restored into an empty repository with exact-head and connectivity checks. CI uploads bundle/hash manifest with requested 90-day retention, downloads and revalidates it before trusted reconstruction and promotion. Atomic push leases archive old control indefinitely under lightweight `archive/patch-queue/<full-old-control-SHA>` and replace `patch-queue`; conflicting archive tags, races or missing atomic support stop promotion. Archive tags are not release versions and never expire with artifacts. Promotion rereads both branch and direct archive object after atomic push, before dispatch. Existing correct tags have no Git compare-only push operation; pre/post checks detect observed changes, not later privileged administrator mutations. Never automatically retag archives or roll back concurrent branch changes.

Built-in job-token promotion explicitly dispatches `channel.yml` bound to the new control SHA, retaining explicit rebuild intent without forcing rebuild. Old runs exit before channel work; dispatch failure fails the run, while next scheduled no-op run recovers ordinary builds. Workflow tree remains byte/mode-identical across automatic refresh. Candidate code never runs with write credentials or production signing secrets. GitHub-hosted disposable runners separate read-only preparation from trusted promotion; live token capability remains a required deployment gate.

## Channels and publication

`.github/workflows/channel.yml` builds both channels on pushes to `patch-queue`, manual dispatch and the six-hour schedule. Source selection and reconstruction live in `.github/downstream/channel_build.py`. Complete published candidates with matching source, upstream and control identities are skipped after provenance and asset-digest checks. Manual dispatch accepts `rebuild` to create a new release from unchanged source. Local automation requires Python ≥3.11.

Stable publishes immutable CalVer releases. Only stable may update Latest, `downstream-feed` and the signed `pacman` repository. Public stable tags use `<upstream-tag>-YYYY.MM.DD.N`, such as `v2.22.3-2026.10.08.2`, with Europe/Berlin dates and a counter per upstream tag/date. Never move a published tag or overwrite its binaries.

Nightly publishes isolated prereleases, never stable update channels. Its AppImage feed is pinned to that immutable nightly; install a newer nightly manually.

`channel.yml` is the only retained workflow. Obsolete branch-preview, legacy release-maintenance and inherited upstream workflows are removed. Stable and nightly publishers reconstruct trusted source from the accepted queue; downloaded source never runs with write credentials.

## Validation

Publication requires Python/real-Git automation tests, TypeScript, Jest, ESLint, Prettier, Linux AppImage and tar.xz packaging, Arch packaging, and a disposable-key pacman signature/download test. Production signing remains confined to the stable publisher. Immutable-artifact checks and upstream/patch-queue freshness checks stop stale or mismatched publication.

Automated checks do not prove desktop interactions or live-account behavior. Follow generated `doc/game-stacking.md` for mouse, keyboard, grid/list, filtering and per-copy action smoke tests. Back up your Heroic profile before testing a custom build; custom packages do not create a separate profile automatically.

Local automation check:

```fish
python3 -m unittest discover -s .github/downstream -p 'test_*.py'
```

In reconstructed application source, use the package manager pinned in `package.json`:

```fish
pnpm install --frozen-lockfile
pnpm codecheck
pnpm test --runInBand
pnpm lint
pnpm prettier
pnpm build
```

## Signing and recovery

Published packages keep upstream names: `heroic-games-launcher-bin`, `Heroic Games Launcher`, and `Heroic-…-linux-…` artifacts. Only the local development desktop launcher uses `Custom Heroic`. Downstream versions and release provenance still identify these unofficial builds.

Stable pacman publication uses a dedicated signing-only GPG key, never the personal mail key. Its encrypted backup lives in dotfiles `nix/secrets.yaml` under `signing.heroic_games_launcher.pacman` (private/public key, passphrase, fingerprint, expiry and revocation certificate). Existing fleet SOPS recipients can decrypt it; provisioning does not automatically import it. GitHub Actions uses secrets `PACMAN_SIGNING_KEY`, `PACMAN_SIGNING_PASSPHRASE` and variable `PACMAN_SIGNING_FINGERPRINT`. Clients import only the published public key. Renew before expiry; publisher refuses an unexpected fingerprint change. Never commit plaintext secrets or publish an unsigned pacman update repository.

On reconstruction or validation failure, retain the last published release and repair the queue or tooling on `patch-queue`. Do not overwrite concurrent work or move old release tags. A repaired release receives a new CalVer revision. Published provenance describes the source that actually built each artifact.
